# 羽球 Wiki 簡報生成流程規格

## 目的

本規格定義如何從羽球 Wiki 的既有知識，依使用者指定題目產生一般民眾可閱讀的 HTML 教學簡報。流程採分階段核准：先找 Wiki 證據，再交付大綱供使用者檢查；大綱獲確認後才製作簡報；簡報經使用者檢查並明確核准後才標記為最終版。

## 已確認的需求

- 簡報讀者：一般民眾。
- 簡報格式：HTML 閱讀簡報。
- 頁數：10–15 頁「內容」；封面及參考資料頁不計入此範圍。
- 尺寸：所有投影片使用一致的 16:9 畫布；窄螢幕可在同一畫布內捲動內容，不改變單頁比例。
- 內容來源：先依指定題目搜尋本專案 LLM Wiki。外部搜尋不是預設步驟；若 Wiki 證據不足，先呈報缺口，再詢問是否補充外部來源。
- 工作流程：Wiki 搜尋 → 生成大綱 → 使用者審閱大綱 → 製作簡報 → 格式自檢 → 使用者審閱簡報 → 使用者確認最終版本。

## 輸入

每次開始時取得使用者的簡報題目。未提供的資訊採以下預設，若會大幅影響內容則先詢問：

- 讀者：一般民眾。
- 目的：用簡明易懂的方式介紹指定主題，不提供個人診斷、治療或復健處方。
- 內容頁數：10–15 頁，不含封面及參考資料頁。
- 語言：繁體中文。
- 風格：清楚、易讀、避免不必要的術語。

## 流程與核准關卡

### 1. 依題目搜尋 Wiki

1. 先讀 `wiki/index.md`，再讀相關 `wiki/topics/` 和 `wiki/papers/` 頁面。
2. 整理一份內部證據清單：可用主張、支持文獻、Wiki 頁面連結與 PDF 頁碼、研究對象與限制。
3. 只使用可從 Wiki 回溯到核心 PDF 的事實與結論。問卷、相關或迴歸結果不可講成因果；不同研究族群的數據不可直接合併。
4. 若資料不足、數字互相矛盾或與題目無關，清楚列出缺口。不要自行填補；如需外部資料，先徵求使用者同意並標示外部來源。

### 2. 產生大綱

提供封面標題及 10–15 頁內容大綱。每一頁至少列出：

- 頁碼與標題。
- 這一頁要讓讀者記住的一句話。
- 預計呈現的重點（建議 1 個核心訊息、最多 3 個支援點）。
- 所依據的 Wiki 文獻頁及 PDF 頁碼；若是跨來源綜整，列出各來源並點出族群或方法差異。
- 適合的視覺呈現方式，例如比較圖、流程、簡單示意圖或短文字；不得用視覺暗示來源沒有支持的結論。

大綱後另外列出參考資料頁預計收錄的文獻，以及任何待查證缺口。

### 3. 使用者審閱大綱（必經關卡）

1. 將大綱交給使用者檢查，詢問是否要調整內容、順序、深度或頁數。
2. 收到明確確認前，不建立 HTML 簡報、不先行製作頁面、不把草稿標示為已核准。
3. 若使用者提出修改，更新大綱並再次提交確認。
4. 只有大綱確認後才進入下一階段。

### 4. 製作 HTML 簡報

1. 按核准大綱製作 HTML 閱讀簡報。預設輸出到 `presentations/<主題短名稱>/index.html`，同一主題的素材放在該主題資料夾中。
2. 封面及參考資料頁不計入 10–15 頁內容頁。首頁列出題目與簡短閱讀提示，結尾附完整參考資料。
3. 每頁聚焦一個主要訊息，採用一般讀者能理解的繁體中文。簡化術語時保留原意，不過度簡化研究限制。
4. 每項研究數據或具體事實均須在頁面標示來源編號或簡短引用，參考資料頁提供作者、年份、題名、出版資訊、DOI（若有）及 PDF 頁碼。
5. 說明不同研究的對象、年份、設計與結果差異；不把舊文建議包裝成最新醫療標準，不將科普內容變成個人診療建議。
6. 版面需適合一般螢幕閱讀、具清楚的標題層級與足夠對比。若可行，使用單一自包含 HTML、避免依賴外部網路資源，並提供鍵盤操作方式。
7. 所有投影片（含封面及參考資料頁）使用一致的 16:9 畫布尺寸；列印版面亦固定相同比例。

### 5. 交付前格式自檢（必經步驟）

在把簡報交給使用者之前，先自行完成以下檢查；發現問題時先修正，再檢查一次：

1. 確認內容頁數在 10–15 頁，封面與參考資料另計，沒有漏頁或重複頁。
2. 確認每一頁（含封面和參考資料）使用相同的 16:9 比例；列印樣式的頁面尺寸也一致。
3. 確認標題、文字、圖表及來源註記沒有溢出、重疊、裁切或難以閱讀的對比問題。
4. 確認每項數據和研究主張都有正確來源標記及 PDF 頁碼；參考資料完整，Wiki 相對連結和本機 PDF 連結有效。
5. 確認鍵盤翻頁、頁碼／進度提示及列印版面等已提供的功能運作正常；窄螢幕內容不改變投影片比例。
6. 優先使用可用且允許的預覽方式逐頁檢查版面。若預覽因工具或安全政策無法開啟，不可繞過限制；改做 HTML 結構、尺寸、連結和引用等靜態檢查，並在交付時明確說明哪些視覺項目無法確認。
7. 自檢通過後，才把版本狀態改為「待使用者審閱」。格式自檢不代表內容已獲使用者核准。

### 6. 使用者審閱簡報（必經關卡）

1. 提供已完成格式自檢的 HTML 檔案或預覽，並附上頁數、內容摘要、來源對照及自檢結果，讓使用者檢查文字、順序、視覺與引用。
2. 明確詢問是否需要修改；未獲確認時，版本狀態保持「待審閱」。
3. 依回饋修改後，重新執行格式自檢，再提供更新版供檢查。每次更新都要確認來源標註與引用仍正確。

### 7. 確認最終版本

1. 只有使用者明確表示確認／定稿後，才將該檔案標示為最終版。
2. 最終交付時提供 HTML 成品位置、實際內容頁數、參考資料及重要限制或未解決缺口。
3. 使用者確認前不得將簡報發布、傳送至外部服務或覆寫其他主題的簡報。

## 版本狀態

每次簡報工作依序使用以下狀態；不得跳過核准關卡：

`Wiki 資料已整理` → `大綱待審閱` → `大綱已確認` → `簡報製作中` → `格式自檢` → `簡報待審閱` → `修訂中`（若有回饋，修改後重做格式自檢）→ `最終版已確認`

## 品質檢查清單

- [ ] 大綱已獲使用者明確確認，才開始製作簡報。
- [ ] 內容頁數在 10–15 頁；封面及參考資料另計。
- [ ] 每頁只有一個主要訊息，閱讀順序清楚，語言符合一般讀者。
- [ ] 所有數據、研究發現與實務主張可回溯到 Wiki 頁面及 PDF 頁碼。
- [ ] 交代不同研究族群和方法差異，未將相關性描述成因果。
- [ ] 健康內容保留必要限制，沒有個人診斷或治療指示。
- [ ] 參考資料完整，版面及連結可供使用者檢查。
- [ ] 交付前已檢查頁數、統一 16:9 尺寸、文字溢出／裁切、引用與連結；若無法目視預覽，已說明靜態檢查範圍及視覺確認限制。
- [ ] 簡報已交給使用者審閱，並在明確核准後才定稿。
